# Что стек делает и чего не делает

## Коротко

- **Панель**: только чтение. Экспортёр раз в 30 с читает `/api/system/stats` и `/api/nodes`; команды
  `targets`, `kuma-sql`, `doctor`, `status` читают `/api/nodes`. Ни одного запроса, меняющего что-либо в
  панели, в коде нет (`grep -rn "PATCH\|POST\|DELETE\|PUT" exporter scripts` находит только POST к
  собственному Prometheus `/-/reload` и к Telegram).
- **Ноды**: агент — один контейнер `node-exporter` (образ `prom/node-exporter`, только чтение
  `/` как `/host:ro`) и одно правило ufw «порт 9100 только для IP сервера мониторинга». xray,
  remnanode, другие контейнеры не трогаются. `--uninstall` снимает и то и другое.
- **Сервер панели**: бэкап читает базу через `pg_dump` (не блокирует панель), архивирует папку
  панели, шифрует и складывает в `/var/backups/remnawave`. Секретного ключа шифрования на сервере нет.
- **Сервер мониторинга**: всё в Docker-контейнерах с префиксом `rwmon-`, данные в томах
  `remnawave-monitoring_*`, файлы в `/opt/remnawave-monitoring`.

## Что открыто в сеть

| порт | что | кому |
|---|---|---|
| 3000 (Grafana) | вход по паролю admin (`GRAFANA_ADMIN_PASSWORD`), регистрация выключена | всем (`GRAFANA_BIND=0.0.0.0`) или только localhost (`127.0.0.1` + `ssh -L`) |
| 3001 (Uptime Kuma) | вход по паролю, страница статуса публичная | как выше (`KUMA_BIND`) |
| 9090 (Prometheus) | без пароля — поэтому **только 127.0.0.1** | сам сервер |
| экспортёр панели, blackbox | без пароля | только внутри сети compose, наружу не пробрасываются |
| node-exporter на сервере мониторинга | без пароля | только внутри сети compose (без host-сети) |
| 9100 на нодах | метрики системы без секретов | только IP сервера мониторинга (ufw); с выключенным ufw установщик отказывается |

Если хотите вообще ничего не открывать — `GRAFANA_BIND=127.0.0.1`, `KUMA_BIND=127.0.0.1` и ssh-туннель.

## Токены и пароли

| что | где | права |
|---|---|---|
| токен панели, пароль Grafana, токен бота | `/opt/remnawave-monitoring/stack/.env` | 600, root |
| токен бота для Grafana | попадает в контейнер Grafana как переменная окружения (contact point); в файлах provisioning его нет — там `${TELEGRAM_BOT_TOKEN}` |
| Telegram в Kuma | внутри базы Kuma (так устроена Kuma) | том docker, root |
| публичный ключ age, токен бота для бэкапов | `/etc/remnawave-backup/backup.env` | 600, root |
| секретный ключ age | **только у вас** (менеджер паролей, бумага) | — |
| ключ offsite `/root/.ssh/remnawave-backup` | на принимающей стороне ограничен `restrict,command="rrsync <папка>"` — может только класть файлы в одну папку | 600 |

Заведите для мониторинга отдельный API-токен панели и отдельного бота — чтобы отозвать независимо.

## Что делает установщик, по файлам

`scripts/install.sh`: ставит Docker (если нет, спросив), копирует репозиторий в
`/opt/remnawave-monitoring`, ссылка `/usr/local/bin/remnawave-monitoring`, запускает мастер. При
повторном запуске обновляет скрипты и конфиги стека, **не трогая** `.env`, `prometheus/targets/*.yml`
и `telegram.yml`. Останавливается, если по этим путям лежит чужое.

`backup/install-backup.sh`: `apt install age rsync`, скрипты в `/opt/remnawave-backup`, конфиг
`/etc/remnawave-backup/backup.env`, юниты `remnawave-backup.timer/service` (и `remnawave-snapshot.*`
на принимающей стороне). Чужие юниты с такими именами не затирает.

`scripts/install-node-exporter.sh` (на ноде): правило ufw → контейнер. Сначала файрвол, потом порт —
чтобы порт ни секунды не был открыт всем. Чужой контейнер с именем `node-exporter` не трогает.

## Нагрузка

Стек на сервере мониторинга: ~400–700 МБ памяти (Grafana + Prometheus + Kuma), диск — Prometheus
растёт примерно на 50–150 МБ в сутки на 20 нод (90 дней — до 10 ГБ; `PROMETHEUS_RETENTION` в `.env`).
Экспортёр — один запрос к панели в 30 с. Агент на ноде — 10–20 МБ памяти, доли процента CPU. Бэкап —
`pg_dump` ночью, с `nice`/`ionice idle`.

## Отмена

- Стек: `sudo /opt/remnawave-monitoring/scripts/uninstall.sh` — контейнеры; про тома с данными и
  `.env` спрашивает.
- Нода: `install-node-exporter.sh --uninstall` — контейнер и правило ufw.
- Бэкапы: `install-backup.sh --uninstall` — скрипты и таймеры; конфиг и копии оставляет (удалите сами).

В панели ничего возвращать не нужно — там ничего не менялось.
