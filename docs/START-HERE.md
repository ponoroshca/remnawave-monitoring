# Пошагово с нуля

Для тех, кто никогда не ставил мониторинг. Нужно: панель Remnawave, отдельный сервер под мониторинг
(любой VPS, 1 ядро / 1 ГБ, Ubuntu 22.04/24.04 или Debian 12), Telegram-бот для тревог. Полчаса.

## Что это и зачем — словарь

- **Панель** — Remnawave, где заведены пользователи и ноды. **Нода** — сервер с xray, которым
  управляет панель. **Мост** — нода в стране клиентов, через которую они выходят на остальные.
- **Prometheus** — база, которая раз в 15 секунд опрашивает «экспортёры» и хранит цифры (90 дней).
- **Экспортёр** — маленькая программа, которая отдаёт цифры в понятном Prometheus виде. Здесь их три:
  экспортёр панели (онлайн, ноды, трафик — из API панели), **node-exporter** (CPU, память, диск
  самого сервера — ставится на каждую ноду), **blackbox** (проверяет с сервера мониторинга, открыт ли порт ноды).
- **Grafana** — графики и **тревоги**: «нода отвалилась», «диск кончается» → сообщение в Telegram.
- **Uptime Kuma** — простая «зелёная/красная» страница статуса, которую не стыдно показать клиентам.
- **age** — программа шифрования: бэкап закрывается **публичным** ключом, а открыть его можно только
  **секретным**, который лежит у вас, не на сервере. Утечёт сервер — копии бесполезны для чужих.

Что где живёт: **сервер мониторинга** (стек в Docker), **ноды** (по одному агенту-контейнеру),
**сервер панели** (скрипт бэкапа по таймеру). Ничего в панели не меняется.

## Шаг 1. Токен панели

Панель → **API Tokens** → **Create** → имя `monitoring` → скопируйте (показывается один раз).
Достаточно прав на чтение.

## Шаг 2. Бот в Telegram

@BotFather → `/newbot` → имя → username (кончается на `bot`) → скопируйте токен `123456789:AAF…`.
Не используйте бота магазина — он занят своей программой. Кому слать, мастер определит сам: попросит
открыть нового бота и нажать Start.

## Шаг 3. Сервер мониторинга — одна команда

```bash
curl -fsSL https://raw.githubusercontent.com/ponoroshca/remnawave-monitoring/main/scripts/install.sh | sudo bash
```

Про «мосты»: если у ноды в панели есть тег `bridge` или в имени есть слово bridge — она мост. Если
мосты не определились, мастер спросит страны мостов (например `RU`). Это только подпись `role` на
графиках и в тревоге про трафик, на работу не влияет.

`ssh -L 3000:127.0.0.1:3000 -L 3001:127.0.0.1:3001 root@203.0.113.5` и открывать `http://localhost:3000`.

## Шаг 4. Открыть Grafana

`http://IP-сервера:3000`, логин `admin`, пароль из вывода мастера. Слева **Dashboards → Remnawave →
«Remnawave — флот»**. Что вы увидите:

- сверху — онлайн, сессии, активные подписки, ноды на связи и отвалившиеся, полоса всего флота;
- «Ноды: состояние» — таблица: связь, страна, сессии, load на ядро (зелёный < 0,7, красный > 0,9),
  свободная память, скорость; «Сессии по странам» — пирог;
- «Трафик к лимиту» — только ноды, у которых в панели задан лимит; «Load на ядро» и «Память» — по всем;
- нижний ряд (CPU, диск, conntrack, порты) заполнится, когда на нодах появятся агенты (шаг 6).

Клик по имени ноды в верхнем меню «Remnawave — нода» — всё то же по одной ноде во времени.

Тревоги: **Alerting → Alert rules** — 11 правил, все «Normal». Правила и точка доставки заведены
файлами (provisioning), поэтому в интерфейсе они только для чтения — так и задумано: пороги
меняются в `/opt/remnawave-monitoring/stack/grafana/provisioning/alerting/rules.yml`, после правки
`docker compose restart grafana` в папке `stack`.

## Шаг 5. Uptime Kuma — страница статуса

1. Откройте `http://IP-сервера:3001`. Kuma спросит, какую базу использовать — **SQLite** → «Далее»,
   затем логин и пароль администратора (любые, это отдельно от Grafana). Запишите их.
2. На сервере: `remnawave-monitoring kuma-sql --apply` — из нод панели появятся мониторы портов,
   проверки панели и подписки, Telegram-уведомление и страница статуса `http://IP:3001/status/status`.
   Перед заливкой делается копия базы Kuma; повторный запуск ничего не дублирует.

## Шаг 6. Агент на каждую ноду

Зайдите на ноду по SSH и выполните команду из вывода мастера (после `--allow-from` — IP сервера
мониторинга). Что делает: один контейнер `node-exporter` + правило ufw «порт 9100 только для этого IP».
Если на ноде выключен ufw, скрипт **откажется** ставить агент — иначе метрики сервера были бы открыты
всему интернету. Включите файрвол (например, `install-node.sh` из
[remnawave-node-kit](https://github.com/ponoroshca/remnawave-node-kit) делает это безопасно) или
осознанно добавьте `--no-firewall`.

Много нод и есть ssh-ключ на все — с сервера мониторинга одной командой:

```bash
remnawave-monitoring targets --ssh-list > hosts.txt
/opt/remnawave-monitoring/scripts/rollout-node-exporter.sh hosts.txt -k ~/.ssh/id_ed25519
```

Через минуту в Grafana у нод появятся CPU, диск, память, conntrack, а «Агент ноды не отвечает»
перестанет гореть.

**Секретный ключ — самое важное, что у вас есть.** Без него бэкапы не открыть никому, включая вас.
Менеджер паролей + распечатка в надёжном месте.

Копия на второй сервер (в другой стране) — чтобы гибель сервера панели не унесла и бэкапы: на втором
сервере `install-backup.sh --offsite-receiver`, он напечатает строку для `authorized_keys`
(ключ отправителя сможет только класть файлы в одну папку) — см. [RECOVERY.md](RECOVERY.md).

Раз в месяц на своём компьютере: `backup/verify-restore.sh <архив> <файл с секретным ключом>` —
поднимет временный Postgres, восстановит копию и скажет «✅ бэкап восстанавливается». Бэкап,
который ни разу не восстанавливали, — не бэкап.

## Шаг 8. Убедиться

```bash
remnawave-monitoring doctor     # все ✅ (ℹ️ — подсказки, не ошибки)
remnawave-monitoring status     # онлайн, сессии, ноды в консоль
```

Дальше система живёт сама: Grafana пишет в Telegram, когда что-то сломалось и когда починилось;
бэкап пишет только если не удался.

## Если что-то не так

| вы видите | что это значит | что сделать |
|---|---|---|
| `панель не ответила` / `токен не принят` | адрес без `https://`, обрезанный токен или самоподписанный сертификат | проверьте адрес в браузере; токен скопируйте заново; на вопрос про сертификат ответьте `y` |
| `docker compose не поднялся … port is already allocated` | порт 3000/3001/9090 занят другой программой | в `stack/.env` задайте `GRAFANA_PORT`, `KUMA_PORT`, `PROMETHEUS_PORT` и `docker compose up -d` |
| в Grafana «No data» везде | экспортёр не достучался до панели | `docker logs rwmon-exporter`; `remnawave-monitoring doctor` |
| нижний ряд дашборда пустой, тревога «Агент ноды не отвечает» | на нодах нет агента или порт 9100 закрыт для сервера мониторинга | шаг 6; на ноде `ufw status` должен показывать `9100/tcp ALLOW <IP мониторинга>` |
| «Порт ноды не отвечает», а нода в панели живая | между сервером мониторинга и нодой блокировка (например, сервер мониторинга в РФ, а нода режется ТСПУ) | это и есть полезный сигнал; если мешает — уберите цель из `stack/prometheus/targets/blackbox.yml` |
| Telegram молчит при тревоге | с сервера в РФ `api.telegram.org` недоступен | [faq](faq.md#telegram) — прокси или другой сервер |
| `СТОП: ufw не активен` при установке агента | файрвол выключен, порт был бы открыт всем | включите ufw или `--no-firewall` осознанно |
| `дамп вдвое меньше вчерашнего` | база панели резко похудела — бэкап не перезаписал старые копии | проверьте панель; если так и должно быть — удалите `/var/backups/remnawave/panel/.last-dump-size` |

## Приложение. Как зайти на сервер, если никогда не делали

Сервер — это компьютер у хостера, к нему подключаются по SSH из терминала. После оплаты
хостер присылает IP-адрес, логин (`root`) и пароль (или вы указали ssh-ключ).

**Windows 10/11:** откройте PowerShell (Пуск → напишите `powershell` → Enter) и введите:

```
ssh root@203.0.113.5
```

(вместо `203.0.113.5` — IP вашего сервера). При первом подключении спросит
`Are you sure you want to continue connecting?` — напишите `yes`. Потом пароль —
**при вводе он не отображается**, это нормально: вставьте и нажмите Enter.

**Mac / Linux:** то же самое в приложении «Терминал».

Вы внутри, когда видите приглашение вида `root@server:~#`. Теперь копируйте команду из
инструкции целиком и вставляйте: в PowerShell — правой кнопкой мыши, в Терминале Mac —
Cmd+V. Enter — выполнить. `sudo` в командах не мешает, даже если вы уже root.

Отключиться — `exit`. Если связь оборвалась посреди установки — просто зайдите снова и
запустите команду ещё раз: скрипты рассчитаны на повторный запуск.
